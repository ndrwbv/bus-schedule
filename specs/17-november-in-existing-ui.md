# Ноябрьское расписание в существующем интерфейсе

Запрос владельца: встроить новую часть с 7 ноября в привычный интерфейс; не заменять его таблицами или новым экраном. Реализация разрешена запросом.

## Критерии
- Home, карточки, избранное и оформление остаются прежними.
- Текущие данные действуют до 6 ноября включительно; граница — полночь Asia/Tomsk.
- С 7 ноября основной список, ближайший автобус, карта и карточка рейса используют новые данные.
- Только прежние пункты «Завтра / Будни / Суббота / Воскресенье»: версия расписания определяется датой выбранного дня. Отдельных ноябрьских пунктов, поясняющего блока и второго переключателя направления нет. Все карточки используют общее направление. Дата рейса сохраняется при открытии карточки.
- Подписи «через парк / через ЛБ» различают оба пути, в том числе обратные.
- Рейс определяется таблицей и столбцом, повторные проезды не теряются; связь двух плеч точная, не подбор по времени.
- Сокращённые первые рейсы не получают выдуманных городских остановок; промежуточные городские остановки считаются отдельно внутри каждого рейса между опубликованными временами.
- Данные приходят с API и кешируются вместе с прежним расписанием. ETag учитывает новую версию.
- Проверить границу 6/7 ноября, праздники, два плеча, повторы, прежние избранные, открытие рейса будущего дня и интерфейс в браузере до выкладки.

## Модель
В ответ API добавляется `schedule.circuits` с датой начала и четырьмя таблицами перевозчика. SQLite с прежним расписанием не перезаписывается до даты перехода. Таблицы — данные для существующих карточек, не новый UI. После перехода приоритет имеет новая модель. Новые данные находятся в `backend/src/data/schedule-2026-11.json`; источник — https://xn--80aasi5akda.online/112s . Все 758 ячеек (749 времён и 9 пропусков) сохраняются.

## Проверка и география

Источник повторно загружен 4 ноября и сопоставлен со всеми ячейками транскрипции. Между опубликованными городскими остановками интерполяция выполняется отдельно внутри рейса. Экстраполяции сокращённых рейсов нет; Левитане не приписываются времена после изменения маршрута.

Положение новых ГОАР и Почты приблизительно: ближайшие платформы OSM 9098641981 и 9044845389 около одноимённых ориентиров (кафе 1360356447, почта 7555697430). Остальные координаты из прежнего справочника. Не выдавать их за геодезическую привязку остановки. Данные OSM: https://www.openstreetmap.org/node/9098641981 и https://www.openstreetmap.org/node/9044845389 .

В браузере проверены прежняя карточка остановки, выбор ноябрьских выходных, список времени с метками ветки, карточка рейса 06:17 за 07.11.2026 и переход к обратному плечу 07:11 с повторными Цветаевой/Почтой. Никаких изменений Home или новых CSS-макетов.

Проверки: 12 frontend-тестов, 17 существующих backend-тестов, ESLint изменённых файлов и обе production-сборки пройдены. Отдельный запуск Express с SQLite в памяти на Node 22 подтвердил сохранение старых данных, добавление четырёх таблиц и ответы 200/304 с no-cache.
