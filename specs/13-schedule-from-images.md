# Фича: расписание с фотографий перевозчика

**Ветка:** `main`
**Создана:** 2026-08-17
**Обновлена:** 2026-09-01 — новый формат таблицы у перевозчика (см. «Формат сентября 2026»)
**Статус:** внедрено

## Контекст

**Зачем:** перевозчик перестал публиковать расписание 112С Word-файлом и присылает
фотографии таблиц. Автоматический парсер (`specs/02-schedule-parser.md`, cron) на них
не работает, поэтому расписание набирается вручную по картинкам. Чтобы пользователь мог
проверить данные, а следующий разработчик — пересобрать их, фотографии лежат в репозитории
и ссылки на них выведены в футере сайта.

**Что есть сейчас:** расписание хранится в SQLite на VDS, отдаётся из `GET /api/schedule`.
Записывается либо пайплайном из Word (`POST /api/schedule/refresh`), либо готовым JSON
(`POST /api/schedule/refresh-json`, `parse_method = 'manual_json'`).

## Формат сентября 2026: одна таблица = круговой рейс

Раньше перевозчик печатал по две таблицы на каждый день (верхняя — в Северный парк,
нижняя — `ВРЕМЯ ВЫЕЗДА` в город) и отдельные листы на будни / субботу / воскресенье.
С 2026-09-01 формат другой:

- **две таблицы вместо трёх**: «БУДНИ ДНИ (ПОНЕДЕЛЬНИК-ПЯТНИЦА)» и
  «ВЫХОДНЫЕ И ПРАЗДНИЧНЫЕ ДНИ». Отдельного субботнего расписания больше нет;
- **один столбец = один круговой рейс** целиком, 17 строк:

  | № строки | Строка у перевозчика | Плечо |
  | --- | --- | --- |
  | 1–3 | Интернационалистов, пл. Ленина, Лагерный сад | из города |
  | 4–8 | Левобережный: Левитана, Синее небо, Этюд, Гармония, Три элемента | из города |
  | 9 | Серебряный бор | разворот: и прибытие, и отправление |
  | 10–14 | ул. А.Ахматовой, Маяк, ул. М. Цветаевой, Маяковского, Набережная | в город |
  | 15–17 | Лагерный сад, пл.Ленина, Интернационалистов | в город |

- будни — 26 столбцов, выходные — 15;
- **столбцы 1–2 будней** (06:05 и 06:30) начинаются сразу от Серебряного бора: это
  выездные рейсы без плеча «из города». Поэтому в `out` 26 рейсов, а в `inLB` 24.

### Что это значит для направлений сайта

| Направление | Что туда попадает |
| --- | --- |
| `inLB` | Всё плечо «из города»: Интернационалистов → пл. Ленина → Лагерный Сад → Левобережный ×5 → Cеребряный бор |
| `out` | Всё плечо «в город»: Cеребряный бор → Анны Ахматовой → Маяк → ул. М. Цветаевой → В. Маяковского → Набережная → Лагерный Сад → пл. Ленина → Интернационалистов |
| `inSP` | **Пусто.** Рейсов «в парк мимо Левобережного» больше нет |

Из этого следуют три правки в коде, без которых данные не разложить:

1. `STOPS_IN_SP` в `stopsInSpOptions.ts` — **пустой массив**. Остановки Набережная,
   В. Маяковского, Поликлиника, ул. М. Цветаевой, Маяк, Анны Ахматовой больше не
   обслуживаются «из города». Список не удалён насовсем: если перевозчик вернёт
   вариант через Набережную, остановки возвращаются сюда, данные — в `inSP`.
2. `STOPS_OUT` в `stopsOutOptions.ts` — добавлена `пл. Ленина` (id `42`): перевозчик
   начал её печатать в обратном плече, и без неё ЦУМ и ТЮЗ интерполировались бы через
   весь 29-минутный перегон Лагерный Сад → Интернационалистов. `Маяк` и
   `ул. М. Цветаевой` тут уже были с `d2ead14` — теперь это их единственное направление.
   Id берутся из свободного диапазона, чтобы не плодить коллизии с `STOPS_IN_LB`.
3. `validateSchedule()` в `backend/src/services/schedule/validator.ts` — направление
   без единого рейса теперь допустимо (у него пропускается правило «минимум
   5 остановок»). Совсем пустое расписание по-прежнему заворачивается.
4. `getScheduleTimes()` в `stops.ts` — подпись ветки («через парк» / «через ЛБ»)
   ставится, только если у дня действительно есть обе ветки. Пока `inSP` пуст,
   «через ЛБ» на каждом рейсе — просто шум: другой ветки не существует.

## Процедура обновления расписания по новым фото

1. Положить фото в `frontend/public/schedule/` под именем `112s-<день>-<ГГГГ-ММ>.jpg`.
   Файлы не пережимать: это первоисточник, на который ссылается сайт.
2. Обновить `SCHEDULE_SOURCE_IMAGES` и `SCHEDULE_SOURCE_DATE`
   в `frontend/src/shared/ui/Footer/scheduleSource.ts`.
3. Расшифровать таблицы. Читать картинку целиком нельзя — цифры сливаются.
   Рабочий способ: найти сетку по тёмным пикселям, нарезать по ней и увеличить.
   Сетку не надо угадывать — она считается:

   ```python
   from PIL import Image; import numpy as np
   a = np.array(Image.open("фото.jpeg").convert("L"))
   dark = a < 140
   rows = [i for i in range(a.shape[0]) if dark[i].sum() > a.shape[1] * 0.4]   # горизонтали
   band = dark[rows[0]:rows[-1]]
   cols = [j for j in range(a.shape[1]) if band[:, j].sum() > len(band) * 0.75]  # вертикали
   ```

   Дальше режем «колонка с названиями + 4 колонки времени» и увеличиваем на 330 %:

   ```bash
   magick "фото.jpeg" -crop 259x469+24+69 +repage labels.png
   magick "фото.jpeg" -crop 189x469+281+69 +repage cols.png
   magick labels.png cols.png +append -resize 330% -sharpen 0x1 chunk.png
   ```

   На фото 2026-09 сетка вышла такой: колонка остановок `24..283 px`, дальше колонки
   времени по `47 px` (первые 7) и по `51 px` (остальные), высота строки `≈26 px`,
   шапка `28 px`.
4. Перепроверить транскрипцию машинно, а не глазами:
   - **таблица выходных — подмножество будней.** На данных 2026-09 все 15 столбцов
     выходных совпали со столбцами будней ячейка-в-ячейку (3, 5, 7, 8, 10, 11, 12,
     13, 14, 15, 16, 18, 19, 21, 23). Это независимая перепроверка 255 клеток;
   - **перегоны между соседними строками** сравнить с медианой по столбцам.
     Отклонение ≥3 мин — повод пересмотреть клетку на увеличении;
   - **время внутри рейса не должно убывать.**
5. Собрать `ISchedule` и записать три файла (транскрипция → payload → сид).
6. Прогнать проверки: формат времени, возрастание, покрытие всех 7 дней,
   и главное — **выравнивание рейсов для интерполяции** (см. ниже).
7. Залить в прод: `ADMIN_TOKEN=... ./scripts/push-schedule.sh`.
   `force: true` в payload обязателен, если менялся состав остановок:
   иначе `VALIDATION_CHANGE_THRESHOLD` (50 % рейсов) завернёт запрос.
   Если менялся и бэкенд (как в сентябре 2026 — валидатор), сначала дождаться
   деплоя из main, потом заливать расписание.
8. Закоммитить фото + три JSON + футер.

## Соответствие названий у перевозчика и лейблов на фронте

| У перевозчика | На сайте |
| --- | --- |
| `Лагерный сад` | `Лагерный Сад` |
| `Серебряный бор` | `Cеребряный бор` (первая буква — **латинская** `C`, так в `STOPS_*`) |
| `Маяковского` | `В. Маяковского` |
| `ул. А.Ахматовой` | `Анны Ахматовой` |
| `Левобережный, Левитана` (и т.д.) | `Левитана`, `Синее небо`, `Этюд`, `Гармония`, `Три элемента` |
| `Маяк` / `ул. М. Цветаевой` (нижнее плечо) | одноимённые остановки в направлении `out` |
| `пл.Ленина` (нижнее плечо) | `пл. Ленина` в `out` |

В августовском формате нижняя таблица печатала петлю целиком, с дублями
(`Поликлиника (М. Цветаевой) [туда]/[обратно]`, `ул. М. Цветаевой [туда]/[обратно]`,
`МАЯК (ул. М. Цветаевой)`) — из них в `out` брались строки «обратно». В сентябрьской
таблице дублей нет: каждая остановка петли напечатана один раз.

Промежуточные городские остановки (`Главпочтамт`, `ТГУ`, `ТЭМЗ`, `Учебная`,
`Новособорная`, `Библиотека ТГУ`, `ЦУМ`/`ТЮЗ`), а также `Поликлиника (Алые Паруса)`
перевозчик не печатает — фронт считает их приблизительно через `interpolateStopTimes()`.

## Edge case: выравнивание рейсов для интерполяции

`interpolateStopTimes()` сопоставляет рейсы **по индексу в массиве**: время для остановки
без данных берётся как доля между `times[i]` предыдущей и `times[i]` следующей остановки
из `STOP_ORDER`. Значит для каждой остановки без данных её ближайшие соседи с данными
обязаны иметь **одинаковую длину массивов**, иначе интерполяция съедет.

На данных 2026-09 это выполняется тривиально — внутри направления и дня у всех остановок
длина массива одинаковая:

| Направление | Будни | Выходные |
| --- | --- | --- |
| `inLB` | 24 у всех остановок | 15 у всех |
| `out` | 26 у всех остановок | 15 у всех |
| `inSP` | — | — |

Ровно ради этого столбцы 1–2 будней (рейсы от Серебряного бора) не попадают в `inLB`:
иначе у `Cеребряный бор` стало бы 26 рейсов против 24 у соседей.

## Остановки Северного парка в направлении «в город»

`Маяк` и `ул. М. Цветаевой` завели в `STOPS_OUT` 2026-08-31 (коммит `d2ead14`): до этого
на них не появлялся переключатель «В город» и человек не видел, когда уехать в центр.
В августовских данных петлю целиком проезжали 11 рейсов в будни и по 6 в сб/вс,
остальные её срезали.

С сентября это уже не «дополнительно», а единственный вариант: **все** рейсы проходят
петлю `Серебряный бор → Анны Ахматовой → Маяк → ул. М. Цветаевой → В. Маяковского`,
и «из города» этих остановок больше нет вовсе. Порядок в `STOPS_OUT` прежний —
после `Поликлиника (Алые Паруса)`, `Маяк` раньше `ул. М. Цветаевой`.

## Аномалии в фото от 2026-09-01

Данные оказались заметно чище августовских: единственное расхождение — опечатка.

1. **Будни, столбец 24**: `пл. Ленина` напечатана как **18-28** между
   `Интернационалистов 19-13` и `Лагерный сад 19-43` — время идёт назад.
   **Исправлено на 19-28**: в остальных 25 столбцах перегон
   Интернационалистов → пл. Ленина всегда ровно 15 минут, а «как напечатано»
   не проходит `validateSchedule()` (времена по остановке должны возрастать)
   и показало бы пользователю автобус, едущий в прошлое.
   Исправление зафиксировано в поле `corrections` транскрипции.
2. **Будни, столбцы 1–2**: спецрейсы 06:05 и 06:30 начинаются от Серебряного бора.
3. **Выходные и праздничные дни** идут одной таблицей — отдельного субботнего
   расписания больше нет.

Остальные аномалии августовских фото (рейс 07:58 с прыжком +54 мин, рейс 11:05
с Гармонией +13 мин и т.д.) в новом расписании отсутствуют.

**Правило прежнее:** странности перевозчика переносятся как напечатано и уходят
в `anomalies`. Исправлять можно только то, что физически невозможно (время назад),
и обязательно с записью в `corrections`.

## Критерии приёмки

- [x] Два фото лежат в репозитории и отдаются с `https://severbus.ru/schedule/…`
- [x] В футере есть текст «расписание набрано с фотографий» и две рабочие ссылки
- [x] Фото не попадают в precache service worker (в `globPatterns` нет `jpg`)
- [x] `ISchedule` проходит `validateSchedule()`: 3 направления × 7 дней, время возрастает
- [x] Проверка выравнивания рейсов для интерполяции проходит для всех направлений и дней
- [x] Таблица выходных сверена с таблицей будней ячейка-в-ячейку
- [x] Сид `backend/src/data/schedule-seed.json` совпадает с payload
- [x] `yarn build`, `npm run build` (backend) проходят, `yarn lint` не даёт новых ошибок

## Что осталось не сделано

- Направление «в город» по-прежнему не показывает время для остановок Левобережного:
  перевозчик их в нижнем плече не печатает. Отдельная задача.
- Остановка `Поликлиника` (вариант «из города») исчезла из списка вместе с `STOPS_IN_SP`.
  Физически автобус мимо неё проезжает, но только «в город», где эта точка называется
  `Поликлиника (Алые Паруса)` и считается интерполяцией.
- Координаты `Маяк`, `ул. М. Цветаевой` и `пл. Ленина` в `STOPS_OUT` приблизительные:
  взяты от одноимённых остановок «из города» со сдвигом на другую сторону улицы.
  Уточнить по факту.
- В `STOPS` пересекаются id между направлениями (`out` 15–19 и `inLB` 15–19), из-за чего
  маркеры карты схлопываются по id. Баг доисторический, к этому расписанию отношения
  не имеет, но при следующей правке остановок его стоит вычистить.
