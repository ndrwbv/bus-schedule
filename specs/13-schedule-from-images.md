# Фича: расписание с фотографий перевозчика

**Ветка:** `main`
**Создана:** 2026-08-17
**Статус:** внедрено

## Контекст

**Зачем:** перевозчик перестал публиковать расписание 112С Word-файлом и присылает
фотографии таблиц. Автоматический парсер (`specs/02-schedule-parser.md`, cron) на них
не работает, поэтому расписание набирается вручную по картинкам. Чтобы пользователь мог
проверить данные, а следующий разработчик — пересобрать их, фотографии лежат в репозитории
и ссылки на них выведены в футере сайта.

**Что есть сейчас:** расписание хранится в SQLite на VDS, отдаётся из `GET /api/schedule`.
Записывается либо пайплайном из Word (`POST /api/schedule/refresh`), либо готовым JSON
(`POST /api/schedule/refresh-json`, `parse_method = 'manual_json'`).

## Процедура обновления расписания по новым фото

1. Положить фото в `frontend/public/schedule/` под именем `112s-<день>-<ГГГГ-ММ>.jpg`.
   Файлы не пережимать: это первоисточник, на который ссылается сайт.
2. Обновить `SCHEDULE_SOURCE_IMAGES` и `SCHEDULE_SOURCE_DATE`
   в `frontend/src/shared/ui/Footer/scheduleSource.ts`.
3. Расшифровать таблицы. Читать картинку целиком нельзя — цифры сливаются.
   Рабочий способ: нарезать таблицу на куски и увеличить каждый.
   Сетка у перевозчика стабильная: колонка с названиями остановок — `0..255 px`,
   дальше колонки времени ровно по `57 px`, высота строки `≈26.85 px`, шапка `28 px`.

   ```bash
   magick "фото.jpg" -crop 255x380+0+26 +repage labels.png       # колонка остановок
   magick "фото.jpg" -crop 399x380+255+26 +repage cols.png       # 7 колонок времени
   magick labels.png cols.png +append -resize 240% chunk.png
   ```

4. Перепроверить на увеличении каждую ячейку, которая ломает шаг между остановками
   (шаг обычно +2…+3 мин внутри Левобережного и +6 мин Набережная → Маяк).
   Расхождения бывают настоящими — тогда они идут в `anomalies` как есть, без «починки».
5. Собрать `ISchedule` и записать три файла (транскрипция → payload → сид).
6. Прогнать проверки: формат времени, возрастание, покрытие всех 7 дней,
   и главное — **выравнивание рейсов для интерполяции** (см. ниже).
7. Залить в прод: `ADMIN_TOKEN=... ./scripts/push-schedule.sh`.
   `force: true` в payload обязателен, если менялся состав остановок:
   иначе `VALIDATION_CHANGE_THRESHOLD` (50 % рейсов) завернёт запрос.
8. Закоммитить фото + три JSON + футер.

## Как раскладываются рейсы по направлениям

Перевозчик печатает две таблицы на каждый день: верхняя — в Северный парк,
нижняя — в город (`ВРЕМЯ ВЫЕЗДА`). Один столбец = один рейс.

- Столбец, где заполнены строки `Левобережный, *` → рейс идёт в `inLB`.
- Остальные столбцы верхней таблицы → `inSP`.
- Вся нижняя таблица → `out`.

Соответствие названий у перевозчика и лейблов на фронте:

| У перевозчика | На сайте |
| --- | --- |
| `Лагерный сад` | `Лагерный Сад` |
| `Серебряный бор` | `Cеребряный бор` (первая буква — **латинская** `C`, так в `STOPS_*`) |
| `ул. В. Маяковского` | `В. Маяковского` |
| `ул. А. Ахматовой` | `Анны Ахматовой` |
| `Поликлиника (А. Ахматовой)` | `Поликлиника (Алые Паруса)` |
| `Левобережный, Левитана` (и т.д.) | `Левитана`, `Синее небо`, `Этюд`, `Гармония`, `Три элемента` |
| `ул. М. Цветаевой, Маяк` (выходные, одна строка) | попадает и в `ул. М. Цветаевой`, и в `Маяк` |
| `Поликлиника (М. Цветаевой)`, `МАЯК (ул. М. Цветаевой)`, `ул. М. Цветаевой` в нижней таблице | не переносятся — таких остановок нет в `STOPS_OUT` |

Промежуточные городские остановки (`Главпочтамт`, `ТГУ`, `ТЭМЗ`, `Учебная`,
`Новособорная`, `Библиотека ТГУ`, `ЦУМ`/`ТЮЗ`) перевозчик не печатает — фронт считает
их приблизительно через `interpolateStopTimes()`.

## Edge case: выравнивание рейсов для интерполяции

`interpolateStopTimes()` сопоставляет рейсы **по индексу в массиве**: время для остановки
без данных берётся как доля между `times[i]` предыдущей и `times[i]` следующей остановки
из `STOP_ORDER`. Значит для каждой остановки без данных её ближайшие соседи с данными
обязаны иметь **одинаковую длину массивов**, иначе интерполяция съедет.

Проверка, которая должна пройти для всех направлений и всех 7 дней: для каждой остановки
из `STOP_ORDER`, которой нет в расписании, найти ближайших соседей с данными и сравнить
`len(prev) == len(next)`.

На данных 2026-08 это выполняется, хотя длины массивов внутри направления разные:

| Направление | День | Рейсов по остановкам |
| --- | --- | --- |
| `inSP` | будни | Интер/Ленина/Лагерный — 14, Набережная — 6, В. Маяковского/Поликлиника — 8, Цветаевой/Маяк/Серебряный бор — 16 |
| `inSP` | сб / вс | 8 / 6 у всех остановок |
| `inLB` | будни / сб / вс | 10 / 6 / 6 у всех остановок |
| `out` | будни | 26 у всех, кроме Поликлиники (Алые Паруса) — 24 |
| `out` | сб / вс | 14 / 12, кроме Анны Ахматовой и Поликлиники — по 6 |

Работает потому, что интерполируемые остановки стоят между соседями с равными длинами:
городские (`ТЮЗ`…`Учебная`) — между `пл. Ленина` и `Лагерный Сад`, `Анны Ахматовой` —
между `Маяк` и `Cеребряный бор`, а у `Набережной`, `Поликлиники` и `В. Маяковского` есть
свои данные, так что интерполяция для них не вызывается.

## Аномалии в фото от 2026-08-17

Оставлены как на картинке — это официальные данные перевозчика, «исправлять» их нельзя.

1. **Будни, в город**, рейс 07:58 от Серебряного бора: ТЮЗ 08:21 → Интернационалистов
   **09:15** (+54 мин вместо ~20). В майской версии в этой ячейке было 08:39.
2. **Будни, в Северный парк**: 10 из 16 рейсов после 12:33 не заходят на Набережную,
   ул. В. Маяковского и Поликлинику — идут `Лагерный сад → ул. М. Цветаевой → Маяк →
   Серебряный бор`. Поэтому у Набережной в будни **6** рейсов «из города», а не 14,
   как было по майским фото.
3. **Будни**, столбцы 1–2: спецрейсы 06:05 и 06:30 начинаются от ул. В. Маяковского.
4. **Суббота, в Левобережный**, рейс 11:05 от Интернационалистов: Этюд 11:43 →
   Гармония **11:56** → Три элемента **11:59** (+13 мин вместо +3). В воскресенье тот же
   рейс идёт 11:43 → 11:46 → 11:49, так что похоже на опечатку перевозчика.
5. **Суббота, в город**, рейс 14:40: Набережная 14:58 → Лагерный сад 15:10 (+12 вместо +6).
6. **Воскресенье, в город**, рейс 12:50: до В. Маяковского 13:07 (+17 вместо +7).
7. **Воскресенье, в Северный парк**, рейс 12:15: Набережная 12:50 → Маяк 12:54 (+4 вместо +6).

## Критерии приёмки

- [x] Три фото лежат в репозитории и отдаются с `https://severbus.ru/schedule/…`
- [x] В футере есть текст «расписание набрано с фотографий» и три рабочие ссылки
- [x] Фото не попадают в precache service worker (в `globPatterns` нет `jpg`)
- [x] `ISchedule` проходит `validateSchedule()`: 3 направления × 7 дней, время возрастает
- [x] Проверка выравнивания рейсов для интерполяции проходит для всех направлений и дней
- [x] Сид `backend/src/data/schedule-seed.json` совпадает с payload
- [x] `yarn build` и `yarn lint` по затронутым файлам проходят

## Что осталось не сделано

- Заливка в прод (`scripts/push-schedule.sh`) требует `ADMIN_TOKEN` — запускает владелец.
- Направление «в город» по-прежнему не показывает время для остановок Левобережного:
  перевозчик их в нижней таблице не печатает. Отдельная задача.
